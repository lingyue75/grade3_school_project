## 二、站点能做什么

这不是一个说明页，而是一个**可在浏览器内运行冲突检测的 MVP**：

| 功能 | 说明 |
| --- | --- |
| 30 样本回放 | 点击「运行冲突检测」即可检出 11 条冲突提示，逐条给出原因、涉及单号与来源 |
| 规则覆盖 | 区域时间窗重叠、装卸口进/撤场重叠（f11）、交接版本不一致、交接三项不齐套（f20/f23） |
| 区域筛选 | 按 A厅 / B厅 / C馆 / D馆 / 会议室 / 多功能厅等缩小检测范围 |
| 类型筛选 | 按四类冲突分别查看，每类标注条数 |
| 三态分布 | confirmed / unconfirmed / missing 计数与占比，`missing` 明确标为「数据不完整」 |
| 样本数据表 | 30 条档期的编号、区域、装卸口、时间窗、版本、状态、来源 |
| 测试与红线 | 五类场景 29 条用例摘要 + 五条不可突破的红线 |
| 结果标记 | 每条提示固定标注「仅提示 · 不锁档」「正式结论须授权人员确认」 |

## 三、前后端一致性验证

站点用原生 JS 复现 `src/venue_schedule_tool/core/conflict.py` 的三类规则，部署前做了逐项对照：

| 对照项 | Python core | 浏览器 JS | 一致 |
| --- | --- | --- | --- |
| 冲突提示总数 | 11 | 11 | 是 |
| 区域时间窗重叠 | 7 | 7 | 是 |
| 装卸口进/撤场重叠 | 1 | 1 | 是 |
| 交接版本不一致 | 1 | 1 | 是 |
| 交接三项不齐套 | 2 | 2 | 是 |
| auto_lock 恒 False | 是 | 是 | 是 |
| 每条含非空原因 | 是 | 是 | 是 |

> 验证方式：`scripts/build_site.py` 生成页面后，抽取内嵌 JS 用 Node 执行 `detectAll`，与 Python `detect_all` 的输出逐类比对，四类分布完全相同。该对照是本次上线放行的前置条件。

## 四、边界（务必如实表述）

| 边界 | 说明 |
| --- | --- |
| 静态演示，非生产系统 | 无服务端、无数据库、无登录鉴权、不写任何业务数据；数据全部内嵌为合成演练样本 |
| 不提供写操作 | 页面没有锁档、改期、提交审批、对外承诺等能力，工具集层面也不提供（f05/f52） |
| 正式系统在哪 | 完整 CLI 冲突检测、30 样本回放与 Agent 编排在本地仓库 `venue-schedule-tool/src/`，**未部署为生产服务** |
| 数据性质 | 30 条档期与 30 条交接均为演练虚构；45 单/月、35 分钟/单等数字不得作为基线或对外引用（REQ-6） |
| 已知口径 | 端点相接按闭区间判为重叠，须业务方书面确认后才能调整（见《测试方案》K-01） |
| 上线前置条件 | Brief 书面原文、Industry 适用性、损失口径、审批人清单仍待补，本站点**不代表试点已获签核或已上线生产** |

## 五、更新与下线

| 操作 | 方式 |
| --- | --- |
| 更新页面内容 | 改 `scripts/build_site.py` → 运行 `python scripts/build_site.py` → 重新发布同一目录（链接保持不变） |
| 更新演练数据 | 改 `data/slots.csv` / `data/handovers.csv` → 重跑构建脚本 → 重新发布 |
| 一致性回归 | 修改规则后须重跑 `pytest tests/ -q` 与 30 样本回放，并重新做第三节的 JS / Python 对照 |
| 下线 | 在应用管理入口将该应用下线，分享链接随即失效 |
