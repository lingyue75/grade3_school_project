# 报销助手智能体系统 · 需求清单（一页纸）

> 版本 v1.0 ｜ 2026-10-30 ｜ 状态：待评审
> 本清单基于需求评审 10 问的答复生成，未答复项按默认假设标注。

---

## 1. 目标与范围

为全体员工与管理员提供**全链路自研**的 Web 报销系统：票据自动归集 → 结构化解析 → 智能填单 → 合规硬拦截 → 预算自动占用 → 现有 OA 审批 → 支付与凭证。

- **一期交付**：到「审批通过并生成付款申请单」为止（含预算占用与释放）。
- **二期**：支付执行、银企对接、会计凭证生成与月结关账。
- **默认假设**：单部门试点 3 个月；不做多法人、多币种、多语言。

## 2. 用户与角色

| 角色 | 核心诉求 | 关键权限 |
|---|---|---|
| 员工 | 少填表、少退单、进度可见 | 提交/撤回单据、查看本人票据池 |
| 部门审批人 | 快速判断该不该批 | 审批、查看本部门预算占用 |
| 财务复核员 | 高风险单据人工兜底 | 复核队列、强制拦截释放、额度回滚 |
| 系统管理员 | 制度变了不给开发提需求 | 规则配置与版本发布、职级标准维护 |
| 审计员 | 出事能追溯 | 只读：证据链日志、规则快照 |

## 3. 关键决策快照

| # | 决策 | 架构后果 |
|---|---|---|
| Q1 | 邮箱/卡包**自动归集**（非税务直连） | 需采集管道 + 跨来源去重，**不建**税务接口集成层 |
| Q2 | 仅**数电票 + 增值税票** | 单一解析器（PDF/OFD/XML），固定 Schema，**不上**多模态模型 |
| Q3 | **配置化规则表 + 版本快照**（非 LLM 判规） | 规则引擎服务 + 规则版本绑定单据，保证可解释、可复现 |
| Q4 | **硬拦截 + 自动占预算** | 预算额度服务（冻结/核销/释放）+ 并发控制 + 补偿对账 |
| Q5 | **复用现有 OA 审批** | 不自研工作流引擎，只做 OA 适配层 + 回调监听 + 状态同步 |
| Q6 | 标准**仅按职级** | 静态标准配置表 + 主数据（职级）同步，RBAC 足够 |
| Q7 | **全新自研，含支付与凭证** | 全链路工量最大，必须分期；需科目/期间/付款单模型 |
| Q8 | **公有云 SaaS + 公有云大模型** | 需数据分级、外发脱敏、模型商合同条款（不训练不留存） |
| Q9 | **Web 门户** | 前后端分离 B/S 架构；IM 入口列为 P2 可选 |
| Q10 | **低风险自动放行、高风险转人工** | 置信度/风险分引擎 + 复核工作台 + 抽检与回溯评估 |

## 4. 核心业务流程

1. **归集**：邮箱 IMAP/卡包定时拉取附件 → 落对象存储 → 入票据池（四元组查重：发票号码+代码+金额+开票日期）。
2. **解析**：数电票优先走 XML/OFD 结构化解析，失败降级 PDF 文本解析，最后降级 OCR。
3. **填单**：智能体按单据模板自动归集票据、匹配费用类型与职级标准，生成草稿（**建议，不代提交**）。
4. **校验**：规则引擎同步执行硬规则 → 不通过则阻断并给出可点击的条款依据。
5. **占预算**：通过后冻结额度 → 推送 OA 审批单（携带预算占用号）。
6. **同步**：OA 回调（通过/驳回/撤回）→ 核销或释放额度；回调丢失由定时对账任务补偿。
7. **复核**：高风险单据进人工复核队列；复核结果回流为评估样本。

## 5. 功能需求

**Must（P0）**
- 票据池：归集、查重、状态机（未使用/已占用/已报销/已作废）、一人一票一单绑定。
- 解析服务：数电票 XML/OFD 解析为结构化字段，字段级置信度输出。
- 规则引擎：规则表配置（适用范围 + 条件表达式 + 动作：阻断/警告/放行）、版本快照、规则变更审计。
- 预算额度服务：按部门/科目/期间冻结、核销、释放；并发安全；对账报表。
- 单据服务：草稿、提交、撤回、状态机、附件与证据链。
- OA 适配层：发起、回调接收、幂等、补偿重试。
- 风险分引擎：命中硬规则 = 高风险转人工；全绿 = 自动放行。
- 复核工作台：队列、复核意见、强制释放、抽检。
- 审计日志：谁在何时用哪条规则版本做了什么决定。

**Should（P1）**
- 制度问答助手（RAG 检索制度文档，仅回答不裁决）。
- 职级标准配置后台、批量导入。
- 数据看板（退单原因 TOP、自动放行率、处理时长）。
- 付款申请单生成（一期只生成，不执行付款）。

## 6. 明确不做（Out of Scope）

- 不自研审批工作流引擎（Q5=A）。
- 不做供应商/采购/合同管理。
- 不做差旅预订（机票火车票由外部渠道，票据入池即可）。
- 不做移动端原生 App（响应式 Web 优先）。
- 一期不做银企支付、会计凭证、多币种多法人。
- 不做通用 DSL 规则语言（用受限表达式，防过度设计）。

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 准确率 | 结构化字段抽取 ≥ 98%（数电票 XML 路径）；重复发票拦截误报率 ≤ 1% |
| 性能 | 单票据解析 ≤ 5s（P95）；单据提交校验 ≤ 2s；支持 100 并发 |
| 安全 | 发票影像加密存储、最小权限、外发大模型前脱敏（人名/银行账号/身份证） |
| 合规 | 数据境内存储；模型商合同约束"不训练、不留存、不可回溯"；操作留痕 ≥ 3 年 |
| 可用 | 核心链路 99.5%；OA 不可用时降级为离线排队，恢复后自动续传 |
| 可审计 | 每个自动决策可回放：输入快照 + 规则版本 + 输出结论 |

## 8. 集成与部署

- **部署**：公有云单 Region（境内），容器化（K8s），对象存储放票据影像，RDS 主备 + Redis 缓存/分布式锁。
- **模型**：公有云大模型（解析兜底、制度问答、异常归因），调用走统一 AI 网关（限流、脱敏、审计、可切换供应商）。
- **集成**：现有 OA（审批发起/回调）、HR/通讯录（职级主数据）、邮箱系统（IMAP，需员工授权）。
- **技术选型建议**：后端 Java（Spring Boot）/ Python（AI 编排 FastAPI）双栈；前端 Vue3；MySQL + Redis + OSS；规则求值用 Aviator/QLExpress；AI 编排用 LangGraph 或自研编排器。

## 9. 验收指标（试点期末）

| 指标 | 目标 |
|---|---|
| 单据一次通过率 | ≥ 85%（试点前基线待测） |
| 自动放行率 | ≥ 60%，且自动放行单据事后差错率 = 0 |
| 员工平均填单耗时 | 下降 ≥ 70% |
| 重复/问题发票拦截 | 召回 100%，误报 ≤ 1% |
| 预算占用对账 | OA 状态与额度状态一致性 100% |
| 财务复核工时 | 下降 ≥ 50% |

## 10. 主要风险与对策

| 风险 | 对策 |
|---|---|
| **预算占用与外部 OA 状态不一致**（最大技术风险，Q4+Q5 叠加） | 占用号贯穿全链路；回调幂等 + 定时对账补偿；每日一致性报表告警 |
| 全新自研含支付凭证，工量失控（Q7） | 严格分期：一期止于付款申请单；支付与凭证二期立项 |
| 公有云处理发票影像的合规审查（Q8） | 数据分级 + 外发脱敏网关 + 模型商合同条款；预留私有化迁移路径 |
| LLM 误判造成错误放行（Q10） | **红线**：硬规则先跑且优先；LLM 只给建议，不得独立放行；高风险一律转人工 |
| 邮箱归集的员工隐私授权 | 明示授权、最小权限、仅取报销相关附件、可随时断开 |
| 制度频繁变更导致规则维护成本 | 规则与代码解耦，规则版本快照绑定单据，业务方自助配置 |
