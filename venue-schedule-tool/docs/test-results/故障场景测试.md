> **企业名称与公开业务方向有公开来源；人物、档期单号、时刻与指标均为演练虚构，不代表企业实际情况。演练结果不得作为实际业务指令（f40），正式结论须授权人员确认（f41）。**

- 执行器：`scripts/run_scenario_tests.py`（真实调用 src/ 模块，无 mock）
- 说明：本场景共 6 条用例；图见文末附图。

| 指标 | 数值 |
| --- | --- |
| 用例总数 | 6 |
| 通过（PASS） | 6 |
| 已知口径（KNOWN） | 0 |
| 失败（FAIL） | 0 |
| 通过率（PASS / PASS+FAIL） | 100.0% |
| 合计实测耗时 | 97.12 ms |
| 单条最长耗时 | 96.81 ms |

> 判定口径：符合预设阈值记 PASS；不符合记 FAIL；实测符合当前实现但业务口径尚待书面确认的记 KNOWN，不计入通过率分母。

## 三、测试过程（逐条）

### F-01 数据文件缺失

| 项 | 内容 |
| --- | --- |
| 输入 / 操作 | io.load_slots(data/__missing__.csv) |
| 预期行为 | 抛 FileNotFoundError，异常可捕获且错误信息含路径 |
| 量化阈值 | 异常类型 =FileNotFoundError =1 |
| **实测输出** | FileNotFoundError（路径 __missing__.csv） |
| 实测指标 | 异常类型=FileNotFoundError |
| 耗时 | 0.23 ms |
| **判定** | **PASS** |
| 备注 / 发现 | 异常可捕获，上层应提示「数据未就绪」而非「无冲突」 |

### F-02 CSV 缺关键列不得静默误判

| 项 | 内容 |
| --- | --- |
| 输入 / 操作 | 临时构造缺 window_start 列的 CSV 并加载 → 参与冲突检测 |
| 预期行为 | 加载或比较阶段暴露异常/空值，不得静默返回「无冲突」结论 |
| 量化阈值 | 静默误判数 =0；异常或空值被显式记录 |
| **实测输出** | 比较阶段抛 TypeError，未静默返回 0 条 |
| 实测指标 | 静默误判数=0；异常暴露=True |
| 耗时 | 96.81 ms |
| **判定** | **PASS** |
| 备注 / 发现 | 已知缺口：缺列时未在上游做字段校验，建议补一个 schema 校验层（REQ-02） |

### F-03 空数据集不崩溃

| 项 | 内容 |
| --- | --- |
| 输入 / 操作 | detect_all([], []) + replay_report([]) |
| 预期行为 | 返回 0 条冲突，报告字段齐全，无异常 |
| 量化阈值 | 冲突数 =0；报告字段数 =5 |
| **实测输出** | 冲突 0 条，报告字段 5 项 |
| 实测指标 | 冲突数=0；报告字段数=5；报告={'total_conflicts': 0, 'all_with_reason': True, 'all_with_source': True, 'auto_lock_used': False, 'review_records': 0} |
| 耗时 | 0.02 ms |
| **判定** | **PASS** |
| 备注 / 发现 | 空数据集安全退化 |

### F-04 LLM 不可用时降级为规则决策

| 项 | 内容 |
| --- | --- |
| 输入 / 操作 | planner.plan(state, ctx, trace) 在未配置模型供应商时调用 |
| 预期行为 | 返回合法决策 dict，type 在允许集合内，无异常 |
| 量化阈值 | 异常数 =0；决策 type 合法 =1 |
| **实测输出** | plan 返回 type=tool |
| 实测指标 | 决策 type=tool；异常数=0 |
| 耗时 | 0.04 ms |
| **判定** | **PASS** |
| 备注 / 发现 | 未配置 LLM 供应商时走规则策略器，功能不中断 |

### F-05 未知工具名不导致崩溃

| 项 | 内容 |
| --- | --- |
| 输入 / 操作 | tools.execute('no_such_tool', {}, ctx) |
| 预期行为 | 返回 ok=False / code=5101 而非抛出 |
| 量化阈值 | 拒绝 =1；异常数 =0 |
| **实测输出** | ok=False code=5101 |
| 实测指标 | ok=False；code=5101；异常数=0 |
| 耗时 | 0.01 ms |
| **判定** | **PASS** |
| 备注 / 发现 | 统一返回错误信封，不向用户外泄堆栈 |

### F-06 校验令牌过期

| 项 | 内容 |
| --- | --- |
| 输入 / 操作 | 把 stamp.expires_at 改为过去时间后请求变更 |
| 预期行为 | 令牌失效 → 4003 拦截，要求重跑校验 |
| 量化阈值 | 令牌有效 =False；拦截 =1 |
| **实测输出** | 过期令牌 valid=False → code=4003 |
| 实测指标 | 令牌有效=False；ok=False；code=4003 |
| 耗时 | 0.01 ms |
| **判定** | **PASS** |
| 备注 / 发现 | STAMP_TTL=300 秒，过期须重跑校验 |

## 四、实测发现与结论

- **F-01**（PASS）：异常可捕获，上层应提示「数据未就绪」而非「无冲突」
- **F-02**（PASS）：已知缺口：缺列时未在上游做字段校验，建议补一个 schema 校验层（REQ-02）
- **F-03**（PASS）：空数据集安全退化
- **F-04**（PASS）：未配置 LLM 供应商时走规则策略器，功能不中断
- **F-05**（PASS）：统一返回错误信封，不向用户外泄堆栈
- **F-06**（PASS）：STAMP_TTL=300 秒，过期须重跑校验

本场景 **6 条通过、0 条记为已知口径、0 条失败**，通过率 100.0%，合计耗时 97.12 ms。
