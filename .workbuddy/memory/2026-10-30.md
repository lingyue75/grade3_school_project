用户以「企业信息系统架构师」身份做需求评审，10 问答复如下（后续沿用）：
- Q1=2 邮箱/卡包自动归集（非税务直连）｜Q2=1 仅数电票+增值税票｜Q3=2 配置化规则表+版本快照（不用 LLM 判规）
- Q4=2+3 硬拦截 + 自动占预算｜Q5=1 复用现有 OA 审批（不自研工作流）｜Q6=1 标准仅按职级
- Q7=1 全新自研含支付与凭证｜Q8=1 公有云 SaaS + 公有云大模型｜Q9=2 Web 门户｜Q10=2 低风险自动放行/高风险转人工

交付物：`expense-agent/需求清单-一页纸.md` 与 `需求清单-一页纸.html`（A4 一页纸，11 节：目标范围/角色/决策快照/流程/功能/不做/架构分层/非功能/部署选型/验收指标/风险对策）。

架构立场（已定，别再改）：
- 硬规则引擎优先且可解释；LLM 只给建议，不得独立放行；高风险一律转人工。
- 一期止于「审批通过 + 付款申请单」，银企支付与会计凭证放二期（Q7=A 工量最大）。
- 最大技术风险：额度占用与外部 OA 状态一致性 → 占用号贯穿 + 回调幂等 + 定时对账补偿。
## 补充：技术架构方案（Python 栈）
用户追加约束：后端改为**纯 Python FastAPI 异步 + Python 3.11+**，LLM 可换供应商，制度知识库需向量检索。
产出 `expense-agent/架构设计-Python-FastAPI.md`（四层架构图 / src 目录树 / 6 张核心表 + 3 张辅助表 / 第一周 MVT 五天里程碑）。

已定技术决策（后续沿用）：
- 四层：入口层（FastAPI + SSE，中间件链）→ 服务层（不碰 LLM）→ 智能体编排层（LangGraph/自研状态机 + Tool Registry + Guardrails + LLM Provider 抽象）→ 数据层（PostgreSQL16 + pgvector + Redis + 对象存储 + Celery）。
- 层间纪律：入口层不碰 ORM；服务层不碰 LLM；编排层只能通过 Tool 调服务。
- 知识库**按条款切片**（不按字数），每片带 metadata（适用职级/生效区间/制度版本），检索做结构化过滤 + 向量召回 + BM25 混合。
- 金额一律 numeric(14,2)；草稿保存 grade_code_snapshot 与 ruleset_version 快照；messages 表存 retrieval_refs 与 prompt_version 以支持回溯。
- 第一周 MVT = 问制度（带条款引用）+ 一句话建单 + 硬规则阻断；不做鉴权/预算/OA/前端美化。失败判据：问答准确率<50% 改切片策略；工具调用成功率<80% 改槽位填槽式确定性流程。
