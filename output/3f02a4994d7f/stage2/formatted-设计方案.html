一、设计背景与目标

1.1 问题定位

问题不在"要不要上 AI 排期"，而在档期申请链路的交接点——版本、未结项与责任在交接时丢失，导致重复核对（f01 链路：意向询期 → 占档确认 → 合同审核 → 进撤场计划）。

1.2 业务目标

减少重复核对，同时保留人工确认与可追溯来源（f00）。这不是把判断交给系统，而是把重复比对的人力省下来，让每次变更都有据可查。

1.3 设计目标

一是建立统一关联编号，使跨工具（服务台 / 台账 / 文件库）比对从人工串联降为一次核对（REQ-2）。二是在提交与交接节点提供实时冲突提示，每条提示说明原因并携带来源（f02 / f40）。三是交接三项齐套检查（接收人 / 版本 / 未结项），缺项自动拦截（f20 / f23）。四是全流程留痕，支持 30 样本回放审计（f02 / f41）。

二、业务范围与红线

2.1 范围内（单批次试点）

单批次场馆档期申请的冲突提示（区域时间窗重叠、装卸口进/撤场重叠、交接版本不一致、交接三项不齐套）；只读数据集成（脱敏后的档期数据导出与字段对齐）；人工复核记录与授权确认留痕。

2.2 范围外（红线）

不自动锁档、不签约、不承诺容量（f05 / f52）；对外承诺仍由业务人员确认（f52）；演练结果不得作为实际业务指令（f40）；跨企业资料只按明确授权范围访问（f41）。

三、总体架构

系统由五层构成，数据单向只读流入，决策权始终在人工侧：

层次能力对应需求
统一编号层分配 DLG-YYYYMMDD-NNNN，串联三类工具REQ-2 / f30
数据汇聚层对齐场馆区域、时间窗、进撤场时长、版本、占档状态；缺失值与未确认值分列REQ-2 / f31
冲突检测层区域时间窗重叠、装卸口重叠、版本不一致检测REQ-1 / f11

复核留痕层来源校验、授权确认、复核台账、回放审计REQ-3 / f40 / f41

四、关键设计

4.1 占档状态三态模型

为避免"把没填误判成没占档"（f31），占档状态设计为三态：confirmed（已确认占用）、unconfirmed（已填报但未确认，参与冲突判定）、missing（字段缺失，不参与时间窗判定，单独输出数据不完整提示）。

4.2 冲突规则

区域时间窗重叠：不同申请在同一场馆区域的时间窗（含进撤场时长）重叠，提示并要求人工确认以哪一版本为准。

装卸口进/撤场重叠：不同申请在同一装卸口的进撤场时间重叠，提示需翻原始版本判断责任节点（f11）。

交接版本不一致：交接引用版本与台账最新版本不一致，提示未列明最新版本（f23）。

交接三项不齐套：接收人 / 版本 / 未结项缺一，拦截并退回补充（f20 / f23）。

四类规则独立判断、互不屏蔽：不同区域也可能共用装卸口，两类提示各自成立。

4.3 人工确认与授权

每条提示默认 requires_human_confirm 为真、auto_lock 为假（恒不锁档）。来源为空的提示不得进入正式流转（f40）。正式结论只能由授权人员名单内的复核人确认（f41）；名单未配置时默认收紧、拒绝确认。

4.4 可追溯性

每条提示输出类型、涉及申请编号、原因、来源、是否需人工确认、是否自动锁档六项，与复核记录一并写入台账，支持按申请回放。

五、数据流与集成方式

一、客户诉求进入统一入口，系统自动分配统一关联编号。二、只读抽取服务台、业务台账、文件库中的关键字段，按编号汇聚。三、冲突检测与齐套检查实时计算，产出含原因与来源的提示。四、提示推送给具名接收人，人工确认后进入合同审核与进撤场计划。五、全过程写入复核台账，供回放与审计。

集成边界：试点阶段仅做只读（脱敏导出），不回写占档状态；如需回写，须另行走权限申请与审批（由秦芮与傅景确认边界）。

六、验收口径与测试设计

6.1 验收标准（f02）

回放 30 个档期样本，识别全部已标注冲突且说明原因；每条结果附来源与人工复核记录（f41）。

6.2 测试覆盖

统一编号格式校验与生成（正常 / 边界 / 异常）；区域时间窗重叠与装卸口重叠检测（含进撤场时长口径）；缺失值不判定为"未占档"；交接三项齐套检查（区分"没填"与"确认无"）；版本不一致检测；授权确认与来源缺失拒绝流转。

6.3 自检结果

执行 examples/demo.py：样本 30，识别提示 11 条，已标注档期冲突识别 7/7，全部含原因与来源，auto_lock 为假。

七、风险与治理

风险处置责任
销售与运营时间口径不一（f50）口径书面统一后启动试点叶书起草 / 顾明岚签署
越权锁档或自动承诺硬性禁用自动锁档；提示默认需人工确认傅景
来源不清进入流转无来源提示拒绝流转傅景
数据质量差缺失与未确认分列，抽样核对秦芮
基线缺失导致收益不可量化先建口径再谈收益（REQ-6）顾明岚

停止权归属傅景（f04）；未经预算审批人确认不进入采购与对外承诺。

八、实施计划

一、口径与样本确认（责任：顾明岚、叶书）。二、只读原型与脱敏导出（责任：秦芮）。三、30 样本回放验收（责任：傅景、唐映秋）。四、单批次试点评审与复盘（责任：顾明岚）。

里程碑：口径确认 → 只读原型 → 样本回放 → 试点评审。
