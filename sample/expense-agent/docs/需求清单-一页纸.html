报销助手智能体系统 · 需求清单（一页纸）

v1.0 ｜ 2026-10-30 ｜ 状态：待评审
依据「需求评审 10 问」答复生成

1｜目标与范围

为全体员工与管理员提供全链路自研的 Web 报销系统：票据自动归集 → 结构化解析 → 智能填单 → 合规硬拦截 → 预算自动占用 → 现有 OA 审批 → 支付与凭证。

  • 一期：交付到「审批通过 + 生成付款申请单」（含预算占用与释放）。
  • 二期：支付执行、银企对接、会计凭证、月结关账。
  • 默认假设：单部门试点 3 个月；不做多法人/多币种/多语言。

2｜用户角色

角色核心诉求 / 关键权限
员工少填表、少退单、进度可见；提交/撤回、查看本人票据池
部门审批人快速判断该不该批；审批、看本部门预算占用
财务复核员高风险兜底；复核队列、强制拦截释放、额度回滚
系统管理员制度变更不提开发需求；规则配置与发布、职级标准维护
审计员只读：证据链日志、规则版本快照

3｜关键决策快照（决定架构）

#决策架构后果
Q1 采集邮箱/卡包自动归集需采集管道 + 跨来源去重；不建税务直连层
Q2 票种仅数电票 + 增值税票单一解析器（XML/OFD/PDF），固定 Schema，不上多模态
Q3 制度配置化规则表 + 版本快照规则引擎服务；规则版本绑定单据，可解释可复现
Q4 管控硬拦截 + 自动占预算额度服务（冻结/核销/释放）+ 并发控制 + 对账补偿
Q5 审批复用现有 OA不自研工作流；只做适配层 + 回调 + 状态同步
Q6 标准仅按职级静态标准表 + 主数据同步，RBAC 足够
Q7 边界全新自研含支付凭证工量最大，必须分期；需科目/期间/付款单模型
Q8 部署公有云 + 公有云大模型数据分级、外发脱敏、模型商合同条款约束
Q9 入口Web 门户前后端分离 B/S；IM 入口列 P2
Q10 自动化低风险自动放行 / 高风险转人工风险分引擎 + 复核工作台 + 抽检回溯

4｜核心流程

1 归集▸ 2 解析▸ 3 填单▸ 4 校验▸ 5 占预算▸ 6 同步 OA▸ 7 复核/放行
  • 归集：IMAP/卡包定时拉取 → 对象存储 → 票据池（四元组查重：号码+代码+金额+日期）。
  • 解析：数电票 XML/OFD 优先，降级 PDF 文本，最后 OCR；输出字段级置信度。
  • 填单：自动归集票据、匹配费用类型与职级标准，生成草稿（建议，不代提交）。
  • 校验：规则引擎同步执行，不通过即阻断并给出条款依据。
  • 占预算：冻结额度 → 推送 OA 单（携带占用号）。
  • 同步：OA 回调核销/释放；回调丢失由定时对账补偿。
  • 复核：高风险进人工队列，结果回流为评估样本。

5｜功能需求（Must / P0）

  • 票据池：归集、查重、状态机（未使用/已占用/已报销/已作废）、一票一单绑定。
  • 解析服务：结构化字段 + 字段级置信度。
  • 规则引擎：范围 + 条件表达式 + 动作（阻断/警告/放行），版本快照与变更审计。
  • 额度服务：按部门/科目/期间冻结、核销、释放，并发安全，对账报表。
  • 单据服务：草稿、提交、撤回、状态机、证据链。
  • OA 适配层：发起、回调接收、幂等、补偿重试。
  • 风险分引擎：命中硬规则 = 高风险转人工；全绿 = 自动放行。
  • 复核工作台：队列、意见、强制释放、抽检。
  • 审计日志：谁、何时、用哪条规则版本、做了什么决定。

Should（P1）：制度问答 RAG（只答不裁）· 职级标准后台 · 数据看板 · 付款申请单生成（不执行付款）。

6｜系统分层（逻辑架构）

接入层Web 门户（Vue3，响应式）；P2 加企微/钉钉入口
采集层邮箱/卡包采集 Job、手动上传、附件预处理
票据池Invoice Pool：去重、验真、状态机、占用绑定
规则层规则引擎服务（配置化规则表 + 表达式求值 + 版本）
额度层预算额度服务：冻结/核销/释放 + 分布式锁 + 对账
单据编排单据服务 + OA 适配层 + 回调监听 + 补偿任务
智能体层AI 网关 → 公有云大模型（填单建议、归因、制度问答）
复核台人工队列、抽检、回溯评估、样本回流
基础服务主数据（职级/组织）、RBAC、审计日志、对象存储、消息通知
二期付款单、银企支付、会计凭证、科目与期间管理
红线：硬规则先跑且优先级最高；LLM 只输出建议，不得独立放行；高风险一律转人工。

7｜明确不做（Out of Scope）

  • 不自研审批工作流引擎（复用 OA）。
  • 不做供应商/采购/合同管理、差旅预订。
  • 不做原生移动 App（响应式 Web 优先）。
  • 一期不做银企支付、会计凭证、多币种多法人。
  • 不做通用 DSL 规则语言（受限表达式即可）。

8｜非功能需求

类别要求
准确率结构化字段抽取 ≥ 98%（数电票 XML 路径）；重复票拦截召回 100%、误报 ≤ 1%
性能单票据解析 ≤ 5s（P95）；提交校验 ≤ 2s；支持 100 并发
安全影像加密存储、最小权限；外发大模型前脱敏（人名/银行账号/身份证）
合规数据境内存储；模型商合同「不训练、不留存」；操作留痕 ≥ 3 年
可用核心链路 99.5%；OA 不可用时离线排队、恢复自动续传
可审计每个自动决策可回放：输入快照 + 规则版本 + 输出结论

9｜部署与技术选型

  • 部署：公有云境内单 Region，容器化（K8s）；RDS 主备 + Redis（缓存/锁）+ OSS 存影像。
  • 模型：公有云大模型，统一 AI 网关（限流、脱敏、审计、可切供应商）。
  • 集成：OA（发起/回调）、HR 或通讯录（职级主数据）、邮箱（IMAP，员工授权）。
  • 技术栈：Java Spring Boot（业务）+ Python FastAPI（AI 编排）+ Vue3 + MySQL/Redis/OSS；规则求值用 Aviator/QLExpress；编排用 LangGraph 或自研。

11｜主要风险与对策

风险对策
最高 额度占用与外部 OA 状态不一致（Q4+Q5 叠加）占用号贯穿全链路；回调幂等 + 定时对账补偿 + 每日一致性告警
高 自研含支付凭证，工量失控（Q7）严格分期：一期止于付款申请单，支付凭证二期立项
高 公有云处理发票影像的合规审查（Q8）数据分级 + 脱敏网关 + 合同条款；预留私有化迁移路径
高 LLM 误判导致错误放行（Q10）红线：硬规则优先，LLM 仅建议，高风险转人工
中 邮箱归集的员工隐私授权明示授权、最小权限、仅取报销附件、可随时断开
中 制度频繁变更，规则维护成本高规则与代码解耦，版本快照绑定单据，业务方自助配置
