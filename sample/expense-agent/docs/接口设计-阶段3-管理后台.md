## 0. 三个必须先说清的坑（影响你的选择）

### 坑 1：FAISS 不支持"真正删除"
`IndexFlatIP` 没有按向量删除的能力。删除一篇制度文档有三种做法，我建议 **C**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A | `IndexIDMap2 + remove_ids` | 需自维护 chunk_id ↔ 向量 id 映射，重建时易错位 |
| B | 软删 + 检索后过滤 | 最简单，但索引只增不减，长期膨胀 |
| **C（建议）** | **软删 + 检索后过滤 + 定期/达阈值重建索引** | 兼顾简单与体积；后台提供"重建索引"按钮与上次重建时间 |

核心原则：**文档状态以数据库为准，向量库只是可重建的缓存**。这条定下来，后面删除、回滚、迁移 pgvector 都不难。

### 坑 2：提示词模板必须版本化，不能"改了就覆盖"
一旦覆盖，历史问答的解释链就断了——审计时无法回答"当时为什么这么答"。
因此：模板**只增版本不改历史**，`messages.prompt_version_id` 记录当时用的是哪一版，任何版本可一键回滚。**禁止 update 已发布版本的正文**。

### 坑 3：PDF 没有 Markdown 标题，切片策略要分叉
- Markdown：按 `#` 标题切块（阶段1 已实现）。
- PDF：先提取文本 → 按空行分段 → **识别行首编号**（`3.2.1`、`第 5 条`）作为切分边界。
- 阶段1 冒烟已发现的真实问题（`3.2.1` 是正文行不是标题，导致三条住宿标准被并成一片）在阶段3 一并修复：**行首编号识别**成为两种格式共用的切分规则。

## 2. 接口清单

### 2.1 鉴权

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/login` | 工号 + 密码 → 签发 JWT，写入 **HttpOnly Cookie**（SSR 用 Cookie 而非 localStorage，防 XSS 窃取） |
| POST | `/api/v1/auth/logout` | 清 Cookie + 加入 token 黑名单（Redis，剩余有效期内存活） |
| GET | `/api/v1/auth/me` | 当前用户与权限点，前端据此渲染菜单 |

### 2.2 制度知识库

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/admin/knowledge/upload` | `multipart/form-data`；校验扩展名/MIME/大小(≤20MB)；返回 `{document_id, task_id}` |
| GET | `/api/v1/admin/knowledge` | 列表（分页 + 状态筛选） |
| GET | `/api/v1/admin/knowledge/{id}` | 文档详情（含状态、错误信息、分片数） |
| GET | `/api/v1/admin/knowledge/{id}/chunks` | 分片预览（分页），**用于核对切片质量** |
| DELETE | `/api/v1/admin/knowledge/{id}` | **软删**：DB 标 `deleted`，检索层过滤；向量库留待重建 |
| POST | `/api/v1/admin/knowledge/{id}/reingest` | 重新切片向量化（切片策略升级后批量重跑用） |
| POST | `/api/v1/admin/knowledge/reindex` | **重建向量索引**（全量重灌，清掉已软删分片） |
| GET | `/api/v1/admin/tasks/{task_id}` | 摄取进度轮询：`{stage, progress, error_text}` |

摄取阶段：`uploaded → parsing → chunking → embedding → ready / failed`。
**失败必须落库并展示原因**（PDF 加密、扫描件无文本层、embedding 接口报错），不能静默失败。

### 2.3 提示词模板

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/prompts` | 模板版本列表 |
| POST | `/api/v1/admin/prompts` | 新建模板（默认是"草稿"） |
| GET | `/api/v1/admin/prompts/{id}` | 模板详情 |
| PUT | `/api/v1/admin/prompts/{id}` | 编辑**草稿**；已发布版本拒绝修改（5303） |
| POST | `/api/v1/admin/prompts/{id}/publish` | 发布：生成新版本号并**立即生效** |
| POST | `/api/v1/admin/prompts/{id}/activate` | 将某个历史版本设为生效（回滚） |
| POST | `/api/v1/admin/prompts/{id}/archive` | 归档（不删除，保留审计链） |
| GET | `/api/v1/admin/prompts/active` | 当前生效模板（`/chat` 侧调用，带进程内缓存 + 版本号比对） |
| POST | `/api/v1/admin/prompts/{id}/try` | 在线试问：用该模板 + 实时检索跑一句，验证效果再发布 |

**生效机制**：`/chat` 每次请求读缓存中的生效模板（缓存 key = 版本号，发布时主动失效，最坏情况 60s 兜底过期）→ 满足"修改后立即对问答生效"，又不每次打库。

### 2.4 对话审计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/audit/conversations` | 筛选：`user_id` / `employee_no` / `date_from` / `date_to` / `keyword` / `risk_only` / `flagged` / 分页 |
| GET | `/api/v1/admin/audit/sessions/{id}` | 会话详情：消息 + 检索来源 + 提示词版本 + 风险命中 |
| POST | `/api/v1/admin/audit/messages/{id}/flag` | 人工标记/取消疑似违规（带 `note` 说明） |
| POST | `/api/v1/admin/audit/messages/{id}/resolve` | 复核结论：`confirmed_violation` / `false_positive` |
| GET | `/api/v1/admin/audit/risk-rules` | 风险规则列表 |
| PUT | `/api/v1/admin/audit/risk-rules/{id}` | 启停/调整规则（关键词或正则） |
| GET | `/api/v1/admin/audit/export` | 导出 CSV（审计留痕用） |

### 2.5 风险标记的两层机制（**红线：只标记，不判定**）

| 层 | 触发 | 存储 |
|---|---|---|
| 自动 | 命中风险规则（关键词/正则），如"怎么绕过""能不能多开""发票 PS""拆分单据""虚报" | `audit_flags(source='auto', rule_id)`，必须能显示**命中了哪条规则** |
| 人工 | 审计员在页面点"标记"，填写说明 | `audit_flags(source='manual', created_by)` |

**系统不做违规判定**，只给"疑似"标记与命中依据，结论由人复核后写入 `resolve`。这条与项目红线一致：工具只提示，不裁决、不处罚、不自动上报。

## 3. 权限模型

角色两种（`employee` / `admin`），但权限点细分，避免以后加"财务复核员"要改代码：

| 权限点 | employee | admin |
|---|---|---|
| `chat:use` | ✅ | ✅ |
| `knowledge:read` | — | ✅ |
| `knowledge:write`（上传/删除/重建） | — | ✅ |
| `prompt:write`（编辑/发布/回滚） | — | ✅ |
| `audit:read`（查看对话） | — | ✅ |
| `audit:flag`（标记/复核） | — | ✅ |
| `user:manage`（P2） | — | ✅ |

实现：`Depends(require_login)` + `Depends(require_perm("knowledge:write"))`，**接口级校验**，页面渲染只做菜单显隐（不做安全边界）。
管理员的所有写操作同时写入 `audit_logs`（谁改了提示词、谁删了文档，可追溯）。

## 6. 安全要点（SSR 特有）

- **CSRF**：表单 POST 一律带 CSRF token（`itsdangerous` 或自签），配合 `SameSite=Lax`。
- **Cookie**：JWT 存 HttpOnly + Secure（生产）+ `SameSite=Lax`，不存 localStorage。
- **上传校验**：扩展名 + MIME 双重校验、大小限制、保存到非 Web 根目录、文件名随机化（防路径穿越）。
- **XSS**：制度原文、模型输出、用户昵称在模板里一律走 Jinja2 自动转义；仅"分片预览"如需高亮，用白名单处理。
- **审计不可删**：对话记录只增不删（合规留痕），管理员也无删除接口。
- **速率限制**：登录接口按 IP + 工号限流。
